## Engineering rules (learned the hard way)
- **RTL and bidi:**
  - Wrap Latin tokens and numbers inside Hebrew in `<span class="ltr">` (`direction:ltr; unicode-bidi:isolate`), especially around arrows (←) and in buttons.
  - Use child combinators for chip styles (`.chips > span`), because nested `.ltr` spans inherited pill styles before.
  - Wrap text in one span inside flex containers, or flex splits it into items with gaps.
- **Avoid `background-clip:text` gradient headlines** where they may be printed or screenshot. A PDF prints a frame around them, and one in-app browser rendered a box (v1 bug).
- **Motion:**
  - Animate only transform and opacity, never box-shadow.
  - Keep canvas effects light: ≤40 points, batched `Path2D`, ~24fps, start after load, pause when off-screen or hidden.
  - Respect `prefers-reduced-motion`.
  - Scroll-reveal is JS opt-in (`html.js`) with a 4s CSS failsafe, so content can never stay hidden.
- **Mobile:**
  - The hero CTA must be in the first screen (≥85% visible at 360×640).
  - The sticky bottom CTA bar hides while the hero or final CTA is visible (rootMargin −64px for the sticky nav).
  - Tap targets are ≥44px.
- **Link previews (LinkedIn/WhatsApp):** `og:image` must be an absolute URL to a real 1200×627 file (`og.jpg`). Base64 or single-file HTML failed on LinkedIn ("We couldn't load a preview").
- **Artifact CSP:** fonts only from Google Fonts, images as published files, scripts only from the allowed CDNs.
- **Netlify build (`tools/build_netlify.py`):**
  - Self-hosted **subset** fonts (`tools/subset_fonts.py`; ~56KB vs ~125KB).
  - WebP responsive images at 480/640/800/1040.
  - favicon, canonical, robots.txt and `_headers`.
  - A Hebrew `<title>` for SEO: "אוטומציה, חיבור מערכות ו-AI לעסקים | Boost2Business".
- **Cloud environment quirks:**
  - GitHub raw downloads are blocked (403). Get Google-font TTFs from npm (`@expo-google-fonts/*`).
  - Many sites are blocked from the shell. Use WebFetch.
  - Lighthouse needs `CHROME_PATH` pointing at Playwright's Chromium.

## Definition of done ("doctor" loop): all must pass
The commands, in order. All tools run from the repo root. Last verified on v6.1 on 2026-10-26:
- QA PASS on 8 pages × 6 widths, with 0 warnings.
- First screen 10/10 on all pages.
- All 7 demos pass.
- Lighthouse mobile median 99–100 on all four scores; home LCP 1.65 s, 111 KB in 7 requests.
```bash
python3 tools/build_netlify.py                       # site/src → site/dist (self-hosted subset fonts, favicon, sitemap, _headers, _redirects)
python3 tools/serve.py site/dist 8765 &              # Netlify-like local server; note the PID it prints, stop it with: kill <pid>
python3 tools/qa.py http://127.0.0.1:8765/ --crawl   # every linked page × 6 widths + reduced-motion pass → must print RESULT: PASS
python3 tools/firstscreen.py http://127.0.0.1:8765/ http://127.0.0.1:8765/team/chani http://127.0.0.1:8765/solutions http://127.0.0.1:8765/training   # hero CTA ≥85% visible on 10 viewports
python3 tools/demo_test.py http://127.0.0.1:8765        # every demo by tap, keyboard and reduced motion, ≤90 s
bash tools/lighthouse.sh http://127.0.0.1:8765/      # 5 mobile runs (median) + desktop → RESULT: PASS
bash tools/lighthouse.sh http://127.0.0.1:8765/team/chani 5 lh_chani
```
1. **QA** (`qa.py`): 0 FAIL at 360/390/768/1024/1280/1440. It checks:
   - horizontal scroll, JS and console errors, failed requests, broken images;
   - anchors, WhatsApp links, stuck-hidden reveals, one h1, alt text, form labels;
   - CTA tap size ≥ 44 px, `lang`/`dir`, internal links returning 200.
   
   Screenshots go to `qa_out/`. **Look at them.**
2. **First screen** (`firstscreen.py`): the hero CTA (`data-cta="hero"`) is ≥ 85% visible on all 10 viewports, on the home page and on the agent pages.
3. **Lighthouse** (`lighthouse.sh`): the mobile median of 5 runs scores ≥ 95 on Performance, Accessibility, Best Practices and SEO, with LCP ≤ 2.0 s. Desktop should be ~100. Run it on the home page and on at least one agent page.
4. **Independent review:** a fresh subagent that didn't build the site reviews code, CRO, a11y, Hebrew copy and the facts whitelist. Fix everything, then rerun steps 1–3.
5. **Karin's CRO checklist:**
   - The hero gives the problem and the value within 3 seconds.
   - One contrasting CTA with positive first-person text ("אני רוצה…").
   - Social proof is real only: founder story, live demos, pilot offer. Never fake.
   - No exit links (internal pages for each solution are fine).
   - Fast and perfect on mobile.
6. **Ship:**
   - Publish the preview artifact.
   - Zip `site/dist` for Netlify.
   - Send a short Hebrew summary with the numbers. Pair each number with what it means for a visitor.

1. Edit the data or templates.
